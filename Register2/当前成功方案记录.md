# Register2 当前成功方案记录

本文档记录**当前已验证可用的做法**及所解决的问题，便于后续参考与进入下一步开发。

## 一、解决的问题汇总

| 问题 | 原因/背景 | 当前做法（成功） |
|------|-----------|------------------|
| **AI 回复 403 Forbidden** | 1）Anthropic 按请求出口 IP 所在地区限制访问，中国/香港等非支持地区会 403；2）Node.js **不会自动使用系统代理/VPN**，浏览器走代理 ≠ 本地 `node server.js` 走代理。 | 让 Node 通过代理访问 Anthropic：**自动解析代理**（见下），请求从支持地区出口发出。 |
| **重启前能用、重启后 403** | 重启前环境里可能设过 `HTTPS_PROXY`，Node 走了代理；重启后环境变量清空，Node 又不走代理 → 403。 | 不再依赖手动 set：**启动时自动选代理**，重启后双击 bat 即可。 |
| **不想每次手动设 HTTPS_PROXY** | 手动在 bat 里写端口容易忘、不同 VPN 端口不同。 | **自动代理**：环境变量 > Windows 系统代理 > 默认 7890（Clash 常见），一般无需手动设置。 |
| **双击 bat 闪退、只看到 “Freeing 3000”** | “释放 3000 端口”的 `for /f ... taskkill` 在部分环境下导致脚本异常或误杀进程，窗口未执行到 `pause` 就关闭。 | **去掉自动 kill 端口**，简化 bat：只 cd、设密钥、运行 `node server.js`，**结尾统一 `pause`**，端口占用时提示用户先关掉旧服务器窗口。 |

## 二、当前成功做法（要保留）

### 1. 启动方式

- **推荐**：先打开 VPN（建议开启「系统代理」），再双击 **`启动服务器.bat`** 或 **`启动服务器-使用我的密钥.bat`**。
- 若端口 3000 已被占用：先关闭之前开着的服务器窗口，再重新双击 bat。
- 无需在 bat 里或 CMD 中手动设置 `HTTPS_PROXY`。

### 2. 代理逻辑（server.js）

- **自动解析顺序**：  
  1）环境变量 `HTTPS_PROXY` / `ANTHROPIC_PROXY` / `HTTP_PROXY`；  
  2）Windows 系统代理（读注册表 `Internet Settings` 的 ProxyEnable + ProxyServer）；  
  3）默认 `http://127.0.0.1:7890`（Clash 常见端口）。
- 启动时在终端打印当前使用的代理及来源（env / system / default(7890)），便于确认。

### 3. 批处理（bat）

- **不自动杀 3000 端口**，避免闪退和误杀。
- 流程：`cd /d %~dp0` → 提示“若 3000 被占用请先关掉其他窗口” → 设置 `CLAUDE_API_KEY` → 若有 `node_modules` 则 `node server.js`，否则提示 `npm install` → **最后统一 `pause`**，窗口不闪退。

### 4. 其他已保留的改动

- **多模型重试**：403 时先换模型再试，并支持 2 秒后重试一次。
- **messages 规范**：发往 Claude 前将 messages 规范为严格 user/assistant 交替（合并连续同角色消息），避免因格式导致 403。
- **依赖**：`https-proxy-agent` 已加入，用于通过代理发请求。

## 四、Railway 部署「启动几秒后自动 stop」排查

**现象**：服务 start 后几秒内就 stop，心跳在停掉前仍正常，无报错。

**可能原因**：

- Railway 在部署完成后会做健康检查；若未配置 **Healthcheck Path** 或检查失败，会认为部署失败并停止服务。
- **待核实**：有印象在某处看到 Railway 或 Vercel 使用 **8080** 而非 3000；若平台期望服务监听 8080 而当前代码用 3000（或仅用 `process.env.PORT` 且平台未正确注入），健康检查可能连不上，导致部署被判定失败。后续可查平台文档确认默认/注入端口。

**建议操作**（在 Railway 对应 Service 的 **Deploy** 设置里）：

1. 找到 **Healthcheck Path**，点击「+ Healthcheck Path」。
2. 填入：**`/health`**（与 server.js 中的健康检查路径一致）。
3. 保存后重新部署。

**说明**：

- Railway 不提供「监听端口」配置项，会通过环境变量 **PORT** 注入端口；`Register2/server.js` 已使用 `process.env.PORT || 3000`，无需在界面改端口。
- Root Directory 保持 **Register2**（或 `/Register2`，视平台显示为准）即可。
